# ICT Quiz Backend

Маленький сервер на Node.js/Express. Держит ключ OpenAI API в переменной окружения
на сервере — страница теста никогда его не видит. Один эндпоинт:

```
POST /api/generate-questions
Body: {"topics": [...], "perTopic": 5}   // необязательно, есть значения по умолчанию
Ответ: JSON-массив вопросов [{topic, question, options[4], correct_index, explanation}, ...]
```

## Запуск локально

```bash
cd ict-quiz-backend
npm install
cp .env.example .env
# открой .env и впиши свой OPENAI_API_KEY
npm start
```

Сервер поднимется на `http://localhost:3000`. Проверить, что жив:
`http://localhost:3000/health` → `{"ok true}`.

## Куда указывать со страницы теста

В настройках страницы (поле «Адрес API») укажи:

```
http://localhost:3000/api/generate-questions        — при локальном запуске
https://<твой-домен>/api/generate-questions          — после деплоя
```

## Как задеплоить (варианты, от простого к гибкому)

1. **Render.com / Railway.app** — самый быстрый способ. Подключаешь GitHub-репозиторий
   с этой папкой, в настройках сервиса добавляешь переменную окружения
   `OPENAI_API_KEY`, команда запуска `npm start`. Получаешь `https://...onrender.com` —
   это и есть адрес для поля «Адрес API».
2. **Свой VPS** (если ЗКУ уже что-то хостит) — `npm install && npm start` за
   `pm2`/`systemd`, порт проксировать через nginx с HTTPS.
3. **Serverless (Vercel/Netlify functions)** — потребует минимальной адаптации
   `server.js` под формат одной функции-хендлера, сам Express-код при этом
   почти не меняется.

## Безопасность

- `.env` никогда не коммитить в git и не класть в публичный репозиторий.
- Когда деплой стабилен, задай `ALLOWED_ORIGIN` = точный адрес страницы теста —
  так сервер будет принимать запросы только с неё, а не с любого сайта.
- Ключ OpenAI виден только этому серверу; страница и её исходный код его не содержат.
